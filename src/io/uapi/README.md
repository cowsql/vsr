`io_uring.h` and `io_uring/zcrx.h` are the Linux kernel's `include/uapi/linux/io_uring.h` and `include/uapi/linux/io_uring/zcrx.h` (GPL-2.0 WITH Linux-syscall-note, or MIT) of Linux 7.2.6, as `make headers_install` installs them: they were copied from Debian's `linux-libc-dev` 7.2.6-1 (`/usr/include/linux/io_uring.h`, sha256 `8488b223988fe798a9c1c81d13a550a27cac1f096bdd016ef9eb5e51adaf46a7`; `/usr/include/linux/io_uring/zcrx.h`, sha256 `35287ae6d5c63467e68df51283709e1d6d43e6bc0a5f65db4cd284564326c053`) on 2026-09-30.
Local changes: a vendoring note after each SPDX line, and in `io_uring.h` the line `#include <linux/io_uring/zcrx.h>` reads `#include "io_uring/zcrx.h"`, so the copy beside it is used and nothing here includes the system's io_uring headers. `src/io/uring.h` supplies `__DECLARE_FLEX_ARRAY` when the system's `<linux/stddef.h>` predates it (Linux 5.16), so the build needs no particular `linux-libc-dev`.
The previous copy was liburing 2.15's variant of the header (`__kernel_rwf_t rw_flags`, the old `io_uring_napi` padding, no `IORING_NOP_*` file flags, zcrx inline); every constant and layout the executor uses is identical in both, and the one layout that changed, `struct io_uring_napi`, splits the old padding into `opcode` and `op_param`, whose zero values (`IO_URING_NAPI_REGISTER_OP`, `IO_URING_NAPI_TRACKING_DYNAMIC`) are what the old zero padding meant.
The executor needs Linux >= 6.18 at run time (docs/io-design.md, section 2); `src/io/uring.c` asserts at compile time the offsets and sizes of every structure it passes to the kernel.
To refresh them, copy both files from a newer `linux-libc-dev` (or a kernel tree's `make headers_install` output), reapply the note and the include line, update the version and checksums here, then rebuild and run `tests/unit/uring_translate`, `tests/integration/uring_smoke` and `tests/integration/executor_conformance`.
