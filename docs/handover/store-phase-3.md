## Recovery design (src/io/store.c, "Recovery" section; docs/io-implementation.md 6.4 is the step list)
- State machine `enum recovery_stage` driven by `prepare_recovery` (one record per call, stages needing no I/O advance in a loop): STAT (STATX into the ring as scratch) -> SUPERBLOCKS (one READ of both blocks into `store->superblocks`) -> HEADERS (one READ per slot into a pool slab, decoded into the ring as scratch) -> SCAN -> BASE (waits for base_resume) -> FLUSH (FDATASYNC only) -> SUPERBLOCK (`superblock_dirty = 1` then the ordinary prepare_superblock: run + 1, file's slots, floor = recovered sequence) -> FLUSH_AGAIN -> FINISH (READY; the row in a lease region, or NOT_FOUND when no record).
- Reads take a LOAD slot with `sub == RECOVERY_SUB`; `vsr_io_store_complete` routes them to `recovery_read_done`. `recovery.io_slot != NONE` while one is out (close is EBUSY); a fence meanwhile releases the slab at that completion. STATX is a FILE slot op `FILE_STAT`.
- Scan modes (`enum recovery_mode` in `recovery.mode`): SCAN_CHAIN replays through `index_apply`; a range judged bad twice (recovery_judge: `retried`/`retry_offset`, one re-read per position) switches the slot to SCAN_SWEEP (floors only, every 8-aligned position tried); data exhausted -> recovery_successor (candidates: `phase == FREE`, `last_sequence == sequence`, `run >= run`, greatest number; the chosen one is marked SEALED = visited); none -> SCAN_REST sweeps every unvisited slot; then recovery_scan_end. A straddling header/record is re-read from its block when that makes progress (`more`); negative or short chunk reads are judged like bad ranges (sweeping: skip to the next block).
- Per-slot data during recovery lives in the segment table: `number`, `first_sequence = header.last_sequence + 1`, `last_sequence` (the header's, then the last replayed record's), `run` (new field), `used` (block-aligned end of the last valid record), `phase` FREE = candidate/unvisited, SEALED = visited. scan_end frees candidates and abandoned successors (visited, `last_sequence >= sequence`, not `last_slot`), sets the last slot OPEN with `used`, the ring empty (`head = issued = 0`, one extent at `file_head = resume`), readable = written = flushed = durable = sequence, next_segment = max number + 1.
- Floor F (`recovery.durable_floor`): superblock floor, every valid header's floor, every CRC-valid record's flushed (chain + sweeps). `sequence < F` -> CORRUPT. Other CORRUPTs: no valid superblock, geometry mismatch, start slot without the start segment, file shorter than the superblock's slots, a log with records but no identity/hard state, a superblock identity contradicting the replayed one, valid bytes contradicting the log (index_apply). FAILED: more slots than max_segments, STATX error, flush/superblock write errors (also under CONTINUE: `store->error != 0` in prepare_recovery), region exhaustion (impossible).
- Base at recovery: `recovery_scan_end` sets base_state = WANTED with base_kind = BASE_RECOVERY, base_id = anchor.id, base_sequence = client_base (FULL role with a nonzero anchor only). base_begin/record as before; base_end applies at once for BASE_RECOVERY; base_resume(OK) -> retained_rebuild -> FLUSH stage; any other status -> recovery_fail(status). apply_publish's else branch now sets client_base/client_base_id when the id differs from the current base (recovery replay or witness); base_apply(BASE_FROM_FILE) lowers it below uncovered records.
- The row: `recovery_finish` builds vsr_loaded + vsr_recovered in `vsr_io_lease_alloc(replica, NONE, NONE)`'s region with deep copies (`copy_hard`, `copy_checkpoint` incl. manifest bytes; codec's load_region grew by manifest_bytes). The core retains the checkpoint under that lease.
- vsr_io_store_open still ignores `read` (the RECOVERY read carries nothing recovery needs).

## Invariants (in addition to phases 1 and 2)
- No block below the recovered prefix is rewritten: writing resumes at round_up(end of last valid record, block) in the segment holding it; the tail's blocks above it, and every freed slot, may be.
- The run on disk (superblock) is at least the run of every record on media: the run + 1 superblock is flushed before READY in FDATASYNC mode (O_DSYNC covers DSYNC mode).
- `durable` after recovery = the recovered sequence, which is on media (flushed before the superblock carrying it as the floor).
- Segment numbers of headers that never reached media may be reused (next_segment = max durable number + 1).

## Harness additions (tests/unit/store.c)
- Disk model: `disk_flushed` shadow (updated at FSYNC and by O_DSYNC writes), `disk_crash(lose_dirty)` (abandon the instance; revert unflushed blocks when asked; counters/faults reset), `disk_lose_block(at)`, STATX, `flip_armed/flip_offset` (one inverted byte on the next log READ covering it), `disk_track_freeing()` (automatic forget of FREEING slots' never-rewrite bits, called from harness_prepare/complete), `disk_after_recovery()` (recomputes the bits from the store's table: live SEALED slots whole, the current slot below file_head).
- `harness_open_keep(c, keep)` keeps the image and the txn table; `harness_recover(mode, &loaded, &lease)` opens, runs, feeds a wanted base, returns the status; `store_run(t)` submits, runs, feeds a base if wanted, expects OK, snapshots; `expect_recovered(c, sequence)` / `expect_corrupt(c)`; `recover_until_chunk`.
- Base feeds keyed by snapshot id (`feeds[4]`, `feed_of`, `feed_base` = the snapshot module's base load; a wanted id without a feed is CORRUPT); `harness_capture(id)` = the snapshot module's capture (snapshot_clients, base_file_write, capture_offset/end, registers the feed).
- `txn.file_offset` recorded by submit() when packed at once (plain_config has no holds).
- Index snapshots: `snapshot_take()` after each sequence into `snapshots[readable]`, `snapshot_check(sequence)` compares log bounds, ops of [log_begin, log_end) (op, sequence, offset, length, change, index, client; not `previous`), versions (pre subset of post), clients (number, op, retained both ways; in-flight entries forgotten), anchor + manifest, hard view/committed/role, identity, client_base_id, `clients_sequence` post <= pre, retained_begin <= log_begin, the base invariant (a record at or below the base has a base_offset).
- The script: `script_txn(sequence)` (identity at 1, clients at 2, TRUNCATE at %10==0, TRIM at 3, CLIENTS at 5, HARD at 7, client APPEND at 8, PUBLISH at %10==2 from 12 with `harness_capture` at 1 before it, plain appends otherwise), `script_run(from, to)` (SYNC every 4th, RECLAIM after each, snapshots), `script_config(sync_mode)` (segments 2, max 3, segment = header + 2 records, small ring, write-behind 2 blocks), `script_anchor(n)`. Phase 4 can build an image by `harness_open; harness_start(NEW); script_run(1, n)` and crash with `disk_crash`.
- Tests: recover_prefixes (FDATASYNC and DSYNC: every prefix to 44, two recoveries each), recover_torn (every tear of the last write, lost middle block, the run rule), recover_floor (above/at/below F, F from a later record, from the idle superblock, bad PADs, contradicting content), recover_stale (abandoned successor, header lost under a matching old header, header lost under a foreign old header), recover_superblocks (copies, damage, crashed growth, geometry), recover_reread (errors, short and flipped reads on superblocks and chunks, the straddle), recover_modes (NEW/JOIN/RECOVER over empty and nonempty logs, witness, missing file, foreign RESTORE, superblock identity).
