## Decisions (docs/io-design.md section 10; placeholders, the coordinator renumbers)
- 82: the send build and ring. The send slab is a ring addressed by unwrapped 64-bit counters (`header_head` floor, `header_sent` build start, `header_tail` write position; `vsr_io_send.header_begin/end` too); the contiguous writer area at the tail skips to the slab's start when the end holds less than a frame header plus one inline copy and the front holds more. One BUILD per link (`vec_count` vectors in `vecs`, `build_bytes` below `stream_offset`) takes control bytes, encoded messages and stream frames; it goes out when nothing is in flight and an entry is free. A short result leaves the unsent tail of the vectors as the next build (header bytes reserved from the entry's `header_begin`), so stream offsets never rewind. A vector contiguous in memory with the previous one merges. The floor and `notified_offset` are the minimum over the live entries (NOTIFs in any order), falling back to `header_sent`/`sent_offset`.
- 83: queue rules. `end` is assigned when a message's encoding starts (frame length known from the digest), so the messages on a link's stream are a queue prefix. A carrier change or loss RETIRES the prefix: `queued->retiring = 1 + old link`, each completes RETRY once `end <= old->notified_offset` or the old link has no live send (a SEND completion releases the buffers, vsr.h), so completions can leave the queue out of order (`node_queue_remove` shifts and fixes the carrier's `encoding`). A demoted link with a frame half sent or a build pending is closed (-ECANCELED). A node with no carrier and no peer dial pending (`node_peer_pending`: peer links only) retries its waiting (unstarted) messages at once: failed dial, lost carrier, unanswered LINK_WANTED. `vsr_io_node_clear` and shutdown complete everything at once (RETRY / CANCELLED), retiring ones included. A full queue retries the oldest message not on the wire, or refuses the newcomer when all are. `vsr_io_links_send` returns RETRY only when the engine must complete at once: unknown/unauthorized/own destination, undigestible message, unattached replica, closing engine, queue full of messages on the wire; it always wants a link first. `messages_sent`/`messages_retried` count every outcome, the returned RETRY included (the engine must NOT count again).
- 84: stream links. `vsr_io_links_open_stream(io, node, stream, &link)`: EINVAL for an unknown, caller-dialed or own node or a closing engine, ELIMIT without a free link entry; dials at once whatever the backoff; a stream dial's failure schedules nothing for the node (no backoff; `last_error` kept). `link_up(stream)` at establishment, `link_lost(stream, error)` at close, only for links with `link->stream != NONE`. A bound link is never idle-closed; an unbound inbound STREAM link is. `vsr_io_streams_frame` now returns bool (false: the frame stays, retried at every poll). `vsr_io_streams_sent(stream, notified_offset)` is called at every send result and NOTIF of the link (unchanged offset at a zero-copy result). `vsr_io_links_send_frame` contract below.
- 85: TCP_NODELAY. With `options.nodelay`, one SETSOCKOPT record per taken-over socket on its connect slot (idle after the takeover; sub `VSR_IO_STAGE_NODELAY`), FIXED_FILE, `op_flags = IPPROTO_TCP << 16 | TCP_NODELAY`, `addr` a static int 1; the result is ignored (`link_connect_complete` returns at once); a dialed AF_UNIX peer skips it (`link->peer.sockaddr.ss_family`); accepted links do not know their family and try. `nodelay_set` per link.

## Contracts changed (headers)
- link.h: `vsr_io_queued_send.retiring` (was `reserved`); `vsr_io_send.header_begin/end` and `vsr_io_link.header_head/tail/sent` are uint64_t; new `vsr_io_link.vec_count`, `build_bytes`, `nodelay_set`; `VSR_IO_STAGE_NODELAY`; the header comment's send and stream paragraphs; the three public function comments.
- stream.h: `bool vsr_io_streams_frame(...)` (stub returns true, drops); `vsr_io_streams_sent` comment.
- `vsr_io_links_send_frame(io, link, kind, header, header_bytes, payload, count, body_crc, end)`: kind in {REQUEST, CHUNK, END}; `header` is the codec-put body fixed part (8/16/16 bytes); `payload` vectors referenced in place (zero-length ones ignored), pinned until `notified_offset >= *end`; `body_crc` = CRC32C over header then payload bytes, the link pads the body to 8 with zeros from its slab and extends the CRC; `*end` = the link's stream offset after the frame. EBUSY: a send in flight, no free entry, `build_bytes > 0 && build + frame > send_coalesce_bytes`, `vec_count + 1 + payload runs + (pad ? 1 : 0) > 128`, no send slab, or no contiguous ring room for header + pad. ELIMIT: body beyond `frame_limit - 24`. EINVAL: index, state, purpose, kind, NULL `end`.

## What the stream module can rely on
`vsr_io_links_open_stream` and `link_up`/`link_lost`; `send_frame` as above with `vsr_io_streams_sent` as the retry cue after EBUSY (called at every result and NOTIF); inbound frames through `vsr_io_streams_frame` with the slab to retain (`vsr_io_pool_retain`) if the bytes are kept, false to be retried at poll; bind an inbound link with `io->links.links[link].stream = index` at the request frame (gives link_lost and the idle exemption); close with `vsr_io_links_close(io, link, status)`; a link's `notified_offset` is readable directly. Not provided: a send slab guaranteed at establishment (best effort; `send_frame` is EBUSY until one is acquired, and nothing pokes the module then: a pool drought at that moment ends in the stream's inactivity timeout).

## What engine part 2 must call, in order (unchanged from phases 1 and 2, plus the SEND route)
1. `vsr_io_complete`: `vsr_io_slots_resolve`, then for kinds LISTEN, CONNECT (the TCP_NODELAY record included), RECV, SEND, SHUTDOWN call `vsr_io_links_complete(io, slot_index, cqe)`; run `check_closed` after.
2. `vsr_io_poll`: set `io->now`; drain `vsr_io_deadlines_pop` dispatching LINK and DIAL to `vsr_io_links_deadline(io, kind, index, now)`; then `vsr_io_links_poll(io, now)`; then `vsr_io_streams_poll`; drain the forwarded ring; route core SEND to `vsr_io_links_send(io, replica, op.id, op.data, op.arg)` and queue COMPLETE(RETRY) when it returns `VSR_IO_RETRY` (do not count `messages_retried` again); OK means the module completes it later through `vsr_io_engine_complete_core` (the replica's `completions` ring, so a replica must be attached and RUNNING/OPENING; detach only at STOPPED, when the core has no SEND outstanding).
3. `vsr_io_submit`: COMPLETE of a HANDSHAKE op -> `vsr_io_links_handshake_done`.
4. `vsr_io_prepare`: pool provision first, then `vsr_io_links_prepare(io, sqes, capacity, &count)` (capacity >= 4), then the earliest deadline.
5. Public calls map 1:1: `vsr_io_node_set/clear/authorize/node_status`, `vsr_io_adopt`, `vsr_io_close` -> `vsr_io_links_shutdown` (completes queued SENDs CANCELLED; wait for the links to free); `vsr_io_engine_install`, `vsr_io_engine_replica`, `vsr_io_engine_deliver`, `vsr_io_engine_complete_core` are what the module uses.
