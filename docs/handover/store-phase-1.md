## Data structures (struct vsr_io_store; store.c sections in order: Layout; Completions and queues; Ring and extents; Segments; Superblock; Packing; SYNC and flushes; Writes; Open/poll/prepare/complete; Status/close; Phase-2 stubs)
- Ring: `ring`, `ring_size`, `head` (unwrapped next byte), `file_head` (its file offset), `issued` (end of last planned write, jumps over wrap gaps via issue_extent), `retained_floor`. Extents FIFO `extents` (`extents_head`, `extents_count`, `extents_capacity`), each {file_offset, ring_offset, length, last_sequence, segment, header}. Helpers: extent_at(i), extent_newest, extent_begin(segment, header), ring_reserve(n) (drops/trims older extents, never the newest; asserts pin_floor >= floor), ring_append(n), ring_pad, ring_wrap(n), pack_end(seal, n), pin_floor(), written_floor(), memory_only().
- Pins: `pins[regions]` indexed by engine lease index, begin/end unwrapped, UINT64_MAX when free; vsr_io_store_pin(offset,length,lease) returns lease as pin index; vsr_io_store_release unpins (phase 2 adds the slab drop for cold loads). vsr_io_store_hot(offset,length,piece) finds the containing extent.
- Segments: `segments[max_segments]` {number (0 free), first_sequence, last_sequence, used, phase FREE/HEADER/OPEN/SEALED, header_write}, `current`, `slots`, `file_size`, `next_segment`, `start_segment/start_slot` (set at the first segment_open; freeing must update them and set superblock_dirty), `growth` (NONE/ALLOCATING/SUPERBLOCK). segment_free_slot() scans number == 0 in [0, slots); segment_seal(); segment_open(slot) packs the header from identity_set/identity/hard/anchor(id nonzero)/log_begin/log_end/client_base/readable/durable — phase 2 must set identity_set etc. when applying IDENTITY/HARD_STATE/PUBLISH/RESTORE so later headers and superblocks carry the state.
- Index hook: index_apply(store, transaction, offset, length, &status) is called after the copy with the record's file offset/length; return false with a status to fail the STORE (FAILED/CORRUPT) and fence. Recovery replay (phase 3) should call the same function.
- Held STOREs: `stores` ring of {op, transaction (borrowed, pinned by the core), sequence, bytes}; stores_drain() retries in order from poll and after every completion; next_sequence() counts queued ones. Phase-2 hook: in store_pack when slot == NONE, call vsr_io_store_free_segments before requesting growth, and fail FAILED when nothing can free.
- SYNC: `syncs` ring, `flush_pending` (NONE/DUE/WANTED), `flush_target`, `flush_deadline`, `flush_slot`, `idle_deadline`, `packed_since_durable`, `superblock_floor`; syncs_settle() completes in emission order.
- Superblock: `superblock_dirty` (set to request a rewrite; freeing and identity changes should set it), `superblock_pending`, `superblock_next`, `superblock_revision`, superblock_fill() takes slots and floor; superblock_done(cookie = floor).
- Completions: complete(store, op, status, lease, data) into `completions` [3*operations]; vsr_io_store_next_completion drains. store_fail(status) completes every queued op FAILED and the RECOVERY load with `status`; phase 2 must add cold loads there.
- Slot kinds: WRITE (sub = write index), FLUSH (cookie = written at issue), SUPER (cookie = floor), FILE (sub = enum file_op, cookie = FALLOCATE chunk); LOAD reserved for cold reads (case present in vsr_io_store_complete). take_slot() wraps vsr_io_slots_alloc with owner = replica.
- `state_region` (2 epochs with two memberships each + checkpoint + span + manifest_bytes) allocated but unused; `capture_floor` = UINT64_MAX; `clients_capacity` set; `ops`, `versions`, `clients`, `loads` allocated and zeroed.

## Invariants
Extents never cross a segment boundary or the ring wrap and start block-aligned in both spaces; issued <= head and every byte below issued is planned or a wrap gap; writes complete out of order but `written` follows the in-order prefix; a segment in HEADER phase has no record write planned; head - written_floor() <= write_behind + one record before each pack; pack_end() <= pin_floor() + size after each pack.

## Engine part 2 integration (keep for the engine agent)
- Attach: vsr_io_store_check(&opts.store, &core limits, slab_bytes); vsr_io_store_size(..., regions = input_leases + events, ...); tail region alignment = max(block, 4096); vsr_io_store_init(store, metadata, size, tail, tail_size, &opts.store, &limits, regions, tail_region_index, path, AT_FDCWD); the store reads io->replicas[r].options.durability, .deadline_flush, .deadline_sync: set them before the first poll.
- Route the core's RECOVERY LOAD to vsr_io_store_open(store, start_mode, op, read); prepare allocates the log's engine file slot itself. At detach read store->file_slot/log_slot BEFORE vsr_io_store_close (which clears them) and update_file(slot, -1) + vsr_io_engine_slot_free.
- vsr_io_store_complete(io, replica, slot, cqe) needs the slot entry intact; it calls vsr_io_slots_consumed itself. Dispatch kinds WRITE, FLUSH, SUPER, FILE (owner = replica) and later LOAD.
- Call vsr_io_store_poll every poll (arms FLUSH/SYNC handles, converts SYNC's flush request using `now`, retries held STOREs); calling it before the step loop too avoids a one-poll delay.
- Op order within an update: LOADs, STOREs, SYNC, RECLAIM (decision 51). io->stats.writes/flushes are incremented by the store. "<path>/log" must fit 4096 bytes, else the open fails FAILED (-ENAMETOOLONG).

## Open items from phase 1
- FDATASYNC creation: superblocks and header are not flushed until the first SYNC's fdatasync; no directory fsync after creation (engine/snapshot should fsync the directory).
- flush_target waits for written >= the largest pending SYNC sequence (spec 6.2); a held STORE delays earlier SYNCs.
- After a write error under CONTINUE, `written` stops advancing even for earlier writes completing later.
- Decision 57's refusal of stray clients-* files needs a directory listing the executor has no opcode for (phase 3).
- Phase 3: an existing log under NEW/JOIN currently fails FAILED; superblock.slots vs the STATX size when a growth crashed between the FALLOCATE and the superblock write.
- The hold rule's unissued-bytes count includes a wrap gap only between the wrap and the next prepare/completion (bounded by one record).
